# X.509 certificates

[Back to documentation](README.md)

`CryptoBase.X509` depends only on `CryptoBase.Abstractions`; keys are `ISignatureKey`, such as the [signature types of CryptoBase](digital-signatures.md).

## Decoding

```csharp
using System.Security.Cryptography.X509Certificates;
using CryptoBase.X509;

// DER only; a malformed certificate throws ArgumentException. Algorithms, name attribute values, extension contents and the validity period are not checked.
Certificate certificate = Certificate.Decode(der);

// The first CERTIFICATE block, or every one.
Certificate fromPem = Certificate.DecodePem(File.ReadAllText("certificate.pem"));
Certificate[] chain = Certificate.DecodePemAll(File.ReadAllText("chain.pem"));

// Names, extension values and the public key are DER; the BCL types decode them.
string subject = new X500DistinguishedName(certificate.Subject.Span).Name;
string issuer = new X500DistinguishedName(certificate.Issuer.Span).Name;
int version = certificate.Version; // 1, 2 or 3
(DateTimeOffset notBefore, DateTimeOffset notAfter) = (certificate.NotBefore, certificate.NotAfter); // UTC

// The contents of the INTEGER: two's complement, with a leading zero byte if the high bit of a positive number is set.
ReadOnlyMemory<byte> serialNumber = certificate.SerialNumber;

// The whole certificate, the signed part and the issuer's signature.
ReadOnlyMemory<byte> encoded = certificate.Encoded;
ReadOnlyMemory<byte> tbsCertificate = certificate.TbsCertificate;
ReadOnlyMemory<byte> signature = certificate.Signature;

// The subject's key: its algorithm, the bits of subjectPublicKey, and the whole DER to import.
SubjectPublicKeyInfo publicKeyInfo = certificate.PublicKeyInfo;
string keyAlgorithm = publicKeyInfo.Algorithm.Oid;
ReadOnlyMemory<byte> keyParameters = publicKeyInfo.Algorithm.Parameters; // empty if absent
ReadOnlyMemory<byte> keyBits = publicKeyInfo.PublicKey;

// A SubjectPublicKeyInfo on its own; only the structure is checked.
SubjectPublicKeyInfo decoded = SubjectPublicKeyInfo.Decode(spki);

foreach (CertificateExtension extension in certificate.Extensions)
{
    Console.WriteLine($"{extension.Oid} critical={extension.Critical} {extension.Value.Length} bytes");
}

// Key usage, or null if the certificate has none. Validators do not check it: the caller checks the bit it needs.
bool canSign = certificate.KeyUsage is not { } usage || usage.HasFlag(X509KeyUsageFlags.DigitalSignature);

// These extensions decode on first use: Decode accepts a certificate in which one is malformed, and the getter throws
// CryptographicException instead. Each is null without the extension; calls may be concurrent.
AuthorityKeyIdentifier? authorityKeyIdentifier = certificate.GetAuthorityKeyIdentifier();
ReadOnlyMemory<byte>? issuerKeyId = authorityKeyIdentifier?.KeyIdentifier; // null if the field is absent
ReadOnlyMemory<byte>? subjectKeyId = certificate.GetSubjectKeyIdentifier();

// The DNS names as encoded, valid or not, and the IP addresses as 4 or 16 octets.
SubjectAlternativeName? alternativeName = certificate.GetSubjectAlternativeName();
IReadOnlyList<string> dnsNames = alternativeName?.DnsNames ?? [];
IReadOnlyList<ReadOnlyMemory<byte>> addresses = alternativeName?.IPAddresses ?? [];

// An extension value from elsewhere, such as a BCL extension's RawData; a malformed one throws ArgumentException.
SubjectAlternativeName names = SubjectAlternativeName.Decode(rawData);
```

## Host names

```csharp
using CryptoBase.X509;

// RFC 9525: a DNS name or IP address must match the subject alternative name extension; the common name is not used.
// A DNS name may have one trailing dot and letters of either case; a dNSName wildcard "*.example.com" stands for one label.
// Labels that are not ASCII are converted to A-labels with the platform's IDNA conversion, and are rejected in invariant
// globalization mode; A-labels do not depend on the platform.
switch (certificate.MatchHostName("example.com"))
{
    case HostNameMatch.Match: // a dNSName, a wildcard for one label, or an iPAddress identifies the host
        break;
    case HostNameMatch.Mismatch: // none does, or the certificate has no such extension
        break;
    case HostNameMatch.MalformedExtension: // the extension does not decode, so the certificate is malformed
        break;
}

// A host name that is neither a DNS name nor an IP address throws ArgumentException, such as 127.1, which is a shorthand IPv4
// address, or one with a zone or a port. SubjectAlternativeName.MatchesHostName applies the same rules to a decoded value.
bool recognized;

try
{
    recognized = certificate.MatchHostName(serverName) is HostNameMatch.Match;
}
catch (ArgumentException)
{
    recognized = false;
}
```

## Keys and signatures

```csharp
using CryptoBase.Abstractions.Signatures;
using CryptoBase.Signatures;
using CryptoBase.X509;

// The caller imports the key with the implementation it chooses. SignatureKey of CryptoBase gives the type of the key's
// algorithm, such as EcdsaP256, Ed25519 or, for rsaEncryption and id-RSASSA-PSS, RsaKey.
using ISignatureKey issuerKey = SignatureKey.ImportSubjectPublicKeyInfo(issuer.PublicKeyInfo.Encoded.Span);

// Without the CryptoBase package, PlatformRsaKey imports RSA keys, and verifies alike on every platform. It supports the same keys
// and algorithms as RsaKey: RSASSA-PSS only with a salt as long as the hash; an rsaEncryption key allows RSASSA-PKCS1-v1_5 and
// RSASSA-PSS, and an id-RSASSA-PSS key what its parameters allow (RFC 4055, Sec. 3.3). A modulus of 512 to 16384 bits and a
// public exponent of at most 33 bits are supported; other keys throw NotSupportedException.
using PlatformRsaKey rsaIssuerKey = PlatformRsaKey.ImportSubjectPublicKeyInfo(issuer.PublicKeyInfo.Encoded.Span);

// false also for an unsupported signature algorithm; TryGetSignatureAlgorithm tells that case apart.
bool signedByIssuer = certificate.VerifySignature(issuerKey);
bool supported = certificate.SignatureAlgorithm.TryGetSignatureAlgorithm(out SignatureAlgorithm algorithm);

// The AlgorithmIdentifier of a signature algorithm: RsaPkcs1Sha256/384/512, RsaPssSha256/384/512, EcdsaSha256/384/512, Ed25519 and MLDsa44/65/87;
// others throw NotSupportedException. TryGetSignatureAlgorithm also accepts the other encodings that RFC 4055 allows, such as
// RSASSA-PKCS1-v1_5 without parameters.
AlgorithmIdentifier identifier = AlgorithmIdentifier.FromSignatureAlgorithm(SignatureAlgorithm.EcdsaSha256);
ReadOnlyMemory<byte> der = identifier.Encoded;
```

## Self-signed certificates

```csharp
using System.Security.Cryptography;
using System.Security.Cryptography.X509Certificates;
using CryptoBase.Abstractions.Signatures;
using CryptoBase.Signatures.Ecdsa;
using CryptoBase.Signatures.Rsa;
using CryptoBase.X509;

using EcdsaP256 key = EcdsaP256.GenerateKey();
// The subject, a non-empty DER name, is also the issuer; builder.SubjectName returns it.
CertificateBuilder builder = new(new X500DistinguishedName("CN=example.com").RawData);

// Extension values are DER, such as those of the BCL extension types.
SubjectAlternativeNameBuilder alternativeNames = new();
alternativeNames.AddDnsName("example.com");
builder.Extensions.Add(new CertificateExtension("2.5.29.17", false, alternativeNames.Build().RawData));

// Optional: an unsigned big-endian serial number of at most 159 bits; by default, 16 random bytes.
builder.SerialNumber = serialNumber;

// Version 3; the validity period is truncated to whole seconds in UTC.
DateTimeOffset now = DateTimeOffset.UtcNow;
Certificate certificate = builder.CreateSelfSigned(key, SignatureAlgorithm.EcdsaSha256, now.AddDays(-1), now.AddDays(30));

// An RSA key signs with the RSA algorithms that its modulus fits and its AlgorithmIdentifier allows. The certificate holds the
// SubjectPublicKeyInfo that the key exports, so a key imported with id-RSASSA-PSS keeps that AlgorithmIdentifier.
using RsaKey rsaKey = RsaKey.GenerateKey(3072);
Certificate rsaCertificate = builder.CreateSelfSigned(rsaKey, SignatureAlgorithm.RsaPssSha256, now.AddDays(-1), now.AddDays(30));

// Or an RSA key of the platform, such as one in a key store, signs through PlatformRsaKey, which owns it from then on.
using PlatformRsaKey platformRsaKey = new(RSA.Create(3072));
Certificate platformRsaCertificate = builder.CreateSelfSigned(platformRsaKey, SignatureAlgorithm.RsaPkcs1Sha256, now.AddDays(-1), now.AddDays(30));

string certificatePem = PemEncoding.WriteString("CERTIFICATE", certificate.Encoded.Span);
```

## Private keys of X509Certificate2

```csharp
using System.Security.Cryptography;
using System.Security.Cryptography.X509Certificates;
using CryptoBase.Abstractions.Signatures;
using CryptoBase.Signatures;
using CryptoBase.X509;

using X509Certificate2 certificate = X509CertificateLoader.LoadPkcs12FromFile("server.pfx", password, X509KeyStorageFlags.Exportable);

// GetSignaturePrivateKey: a PlatformEcdsaKey (P-256, P-384 or P-521) or PlatformRsaKey that signs through the platform, one signature
// at a time, and works for keys that cannot be exported, such as in a smart card; it never exports the private key.
// SignatureKey.TryImportPrivateKey: a CryptoBase key, EcdsaP256, EcdsaP384, EcdsaP521 or RsaKey, that signs concurrently, or false
// if the platform does not export the key. On Windows and macOS, a PKCS #12 file exports its key only if loaded with
// X509KeyStorageFlags.Exportable. Both methods throw NotSupportedException for other keys.
using ISignatureKey key = SignatureKey.TryImportPrivateKey(certificate, out ISignatureKey? imported) ? imported : certificate.GetSignaturePrivateKey();

// Any ECDsa of the BCL; the PlatformEcdsaKey owns it from then on.
using PlatformEcdsaKey platformKey = new(ECDsa.Create(ECCurve.NamedCurves.nistP256));

// Any RSA of the BCL, which the PlatformRsaKey owns from then on. Like GetSignaturePrivateKey for RSA, the constructor signs once
// with RSASSA-PSS, and once more with RSASSA-PKCS1-v1_5 if that fails, to learn which the key supports; a smart card may ask for a
// PIN then.
using PlatformRsaKey rsaKey = new(RSA.Create(3072));

// Or the caller names the algorithms that the key signs with, and nothing is signed until Sign.
using PlatformRsaKey declared = new(certificate.GetRSAPrivateKey() ?? throw new NotSupportedException(), [SignatureAlgorithm.RsaPkcs1Sha256, SignatureAlgorithm.RsaPkcs1Sha384]);
```

## Validating certificate chains

```csharp
using System.Security.Cryptography.X509Certificates;
using CryptoBase.X509;

// The system's trusted roots, without revocation checks; missing certificates are downloaded.
PlatformCertificateValidator validator = new();

// Or a policy for the roots, revocation, downloads and verification flags; the validator keeps a copy.
PlatformCertificateValidator custom = new(new X509ChainPolicy { RevocationMode = X509RevocationMode.Online });

// The peer's certificate first. ServerAuthentication or ClientAuthentication requires that extended key usage unless the
// policy's VerificationFlags ignore it. HostName must match a DNS name or IP address in the subject alternative names;
// null skips the identity check. The context holds a copy of the list.
CertificateValidationContext context = new(presentedCertificates, CertificateUsage.ServerAuthentication) { HostName = "example.com" };
CertificateValidationContext clientContext = new(clientCertificates, CertificateUsage.ClientAuthentication);

// A deadline, such as a handshake's, bounds each retrieval of certificates, CRLs and OCSP responses; once it has passed,
// nothing is retrieved, and a policy that checks revocation gives RevocationUnknown. TimeProvider is its clock.
CertificateValidationContext bounded = new(presentedCertificates, CertificateUsage.ServerAuthentication)
{
    HostName = "example.com",
    Deadline = DateTimeOffset.UtcNow.AddSeconds(10)
};

// Cancellation is observed until the chain build starts.
CertificateValidationResult result = await validator.ValidateAsync(context, cancellationToken);

if (!result.IsValid)
{
    // Errors holds every reason, most important first; Error is the first.
    Console.WriteLine($"{result.Error}: {result.Message}");
    Console.WriteLine(string.Join(", ", result.Errors));
}

// The path that the platform built, valid or not: the peer's certificate first, then each issuer. PathEnd tells where it ends:
// TrustAnchor, UntrustedRoot (a self-signed root that is not trusted) or MissingIssuer (a partial chain, whose last
// certificate's signature is not verified); None when there is no path.
foreach (Certificate certificate in result.Path)
{
    Console.WriteLine(new X500DistinguishedName(certificate.Subject.Span).Name);
}

bool partial = result.PathEnd is CertificatePathEnd.MissingIssuer;
```

| `Error`, most important first | Cause with `PlatformCertificateValidator` |
| --- | --- |
| `Malformed` | `HostName` is set and the subject alternative name extension does not decode. |
| `UnsupportedAlgorithm` | The platform does not load a certificate, or fails to build the chain. |
| `InvalidSignature` | A signature in the chain is invalid. |
| `Expired` | A certificate is expired or not yet valid. |
| `Revoked` | A certificate is revoked. |
| `UntrustedRoot` | The chain does not reach a trusted root: `PathEnd` is `UntrustedRoot`, or `MissingIssuer` for a partial chain. |
| `NotValidForUsage` | A certificate does not allow the usage, or the chain does not meet an issuance policy. |
| `RevocationUnknown` | The revocation status could not be determined, or was not checked because the deadline had passed. |
| `Unspecified` | Any other status of the chain. |
| `NameMismatch` | The certificate does not identify the host name, or the host name is neither a DNS name nor an IP address; checked whether or not the chain is valid. |

A result is valid exactly when `Errors` is empty; `default(CertificateValidationResult)` holds `Unspecified` alone. Apart from the host name, the platform decides, and `Errors` leaves out the statuses that the policy's `VerificationFlags` ignore. The platforms may report different errors for one chain, for example for issuance policies, name constraints and revocation; `PlatformCertificateValidator` documents the differences.

### Fingerprints

`FingerprintCertificateValidator` validates the peer's certificate by the fingerprints from SDP (RFC 8122, Sec. 5; RFC 8842, Sec. 5.1):

```csharp
using System.Security.Cryptography;
using CryptoBase.X509;

// The values of the peer's a=fingerprint attributes, such as "sha-256 12:DF:3E:…".
FingerprintCertificateValidator validator = new(sdpFingerprints.Select(static value => CertificateFingerprint.Parse(value)));

// Or digests of the certificate's DER encoding. HashAlgorithmName.SHA256 and new HashAlgorithmName("sha-256") name the same
// hash function, whose digest must have 32 bytes; Parse rejects "SHA256", which is not the registered name.
FingerprintCertificateValidator pinned = new([new CertificateFingerprint(HashAlgorithmName.SHA256, expectedDigest)]);

// The value of the local a=fingerprint attribute: "sha-256 " and the digest in uppercase hexadecimal separated by colons.
string local = new CertificateFingerprint(HashAlgorithmName.SHA256, SHA256.HashData(localCertificate.Encoded.Span)).ToString();
```

The validator uses only the fingerprints of the strongest hash function given, SHA-512, then SHA-384, SHA-256 and SHA-1 (RFC 8122, Sec. 5.1); with none of these, the result is `UnsupportedAlgorithm`. Only the digest of the peer's first certificate is compared: a mismatch gives `UntrustedRoot`, and a match a path of that certificate alone, ending at a trust anchor. The validity period, the extensions, the signature, `Usage` and `HostName` are not checked.

### Trust anchors

`TrustAnchorCertificateValidator` validates paths (RFC 5280, Sec. 6) to the trust anchors that the caller gives, such as the roots of a private PKI, Ed25519 or ML-DSA roots, or pinned certificates. It reads no certificate store, and every platform gives the same result.

```csharp
using CryptoBase.Signatures;
using CryptoBase.X509;

// The importer turns a SubjectPublicKeyInfo into a key that verifies; SignatureKey gives an RsaKey for an RSA key. An RSA key for
// which the importer throws NotSupportedException is imported with PlatformRsaKey. The validator owns the keys of the trust
// anchors, so it is disposed.
using TrustAnchorCertificateValidator validator = new(Certificate.DecodePemAll(File.ReadAllText("roots.pem")), SignatureKey.ImportSubjectPublicKeyInfo);

// The most intermediate certificates that are not self-issued (8 by default), and the shortest RSA modulus (2048 by default).
using TrustAnchorCertificateValidator strict = new(roots, SignatureKey.ImportSubjectPublicKeyInfo) { MaxPathLength = 2, MinRsaKeySize = 3072 };

// The time is that of the context's TimeProvider, truncated to the second. Validation uses no network, so it completes
// synchronously and Deadline has no effect; calls may be concurrent.
CertificateValidationContext context = new(presentedCertificates, CertificateUsage.ServerAuthentication) { HostName = "example.com" };
CertificateValidationResult result = await validator.ValidateAsync(context, cancellationToken);
```

Every certificate given is a trust anchor, whose own signature is not verified; a peer's certificate that is one of them is a path of its own. The validator tries each candidate issuer in turn, so a cross-certificate that leads nowhere does not hide one that leads to a trust anchor, and the first path that passes every check is the result.

- The key usage and cA of the peer's certificate are not checked; the caller checks the key usage that it needs.
- Certificate policies are not processed, so a critical certificate policies extension fails the path.
- Name constraints apply to the subject alternative names and, without that extension, to the emailAddress attributes of the subject. Subtrees of forms other than dNSName, iPAddress and rfc822Name are not supported, and fail the paths that they could constrain.
- Signatures with MD2, MD4, MD5, SHA-1, SHA-224 or DSA give `WeakAlgorithm`, as do RSA keys outside `MinRsaKeySize` to 16384 bits, EC keys on curves other than P-256, P-384 and P-521, and DSA keys. Ed448 signatures give `UnsupportedAlgorithm`.

| `Error` | Cause with `TrustAnchorCertificateValidator` |
| --- | --- |
| `Malformed` | An extension that does not decode or breaks its syntax, an empty issuer name, a key that does not decode, or a name that name constraints cannot be checked against. |
| `WeakAlgorithm` | A refused signature algorithm or key. |
| `UnsupportedAlgorithm` | Another signature algorithm, an EC key with explicit parameters, or a key that the importer does not support. |
| `InvalidSignature` | A signature that the issuer's key does not verify. |
| `Expired` | A certificate that is not valid at the time. |
| `UntrustedRoot` | A path that does not reach a trust anchor: `PathEnd` is `UntrustedRoot` for one that ends at a self-signed certificate, and `MissingIssuer` for one that ends without an issuer. |
| `NotValidForUsage` | An extended key usage, basic constraints, key usage, path length or name that the rules refuse, or a critical extension that the validator does not process. |
| `Unspecified` | The search reached its limit on candidate issuers or name comparisons. |
| `NameMismatch` | A host name that the peer's certificate does not identify, or that is neither a DNS name nor an IP address. |

When no path is valid, the result reports the path that came closest, with all of its errors. In `Message`, control characters, line and paragraph separators and unpaired surrogates from the certificates and the host name are written as `\uXXXX`, so it is one line.

### Other validators

Another trust model implements `ICertificateValidator`, and `CertificateValidationResult.Create` builds its results. A validator that wraps another can accept some of what the other rejects and keep the path:

```csharp
using CryptoBase.X509;

// Accepts a chain to a self-signed root that the platform does not trust, such as on a test network; the caller can still
// inspect result.Path and result.PathEnd.
sealed class AnyRootValidator(ICertificateValidator inner) : ICertificateValidator
{
    public async ValueTask<CertificateValidationResult> ValidateAsync(CertificateValidationContext context, CancellationToken cancellationToken = default)
    {
        CertificateValidationResult result = await inner.ValidateAsync(context, cancellationToken);

        // UntrustedRoot also stands for a partial chain, which ends at MissingIssuer, and stays an error then.
        if (result.PathEnd is not CertificatePathEnd.UntrustedRoot)
        {
            return result;
        }

        return CertificateValidationResult.Create(result.Errors.Where(static error => error is not CertificateValidationError.UntrustedRoot), result.Path, result.PathEnd, result.Message);
    }
}
```
